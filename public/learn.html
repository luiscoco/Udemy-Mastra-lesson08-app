Mastra Studio and Execution Inspection

Application labWhat you will learnHow to runArchitecture & workflowCode walkthrough
01

Launch the real Studio

npm run studio starts the pinned Mastra CLI on port 4208. The host, agents, workflow and telemetry are actual SDK components.

02

Record native execution evidence

A registered two-step workflow creates a trace. The app flushes the native exporter and checks the persisted trace instead of manufacturing a timeline.

03

Inspect the lifecycle

Follow validated input, lookup, formatting and the final task result. Traces describe observed execution rather than guaranteed access to hidden reasoning.

04

Separate two outcome levels

The SDK can complete a workflow whose business result reports a missing lesson. Inspect the task contract as well as runtime success.

05

Use bounded local storage

Trace data is written to this app's ignored .mastra directory. Metrics aggregation and external telemetry export are not configured.

06

Diagnose before editing

Locate whether the issue is input, registration, a tool, a workflow step or provider access. Change the relevant boundary and rerun the same task.

Check your understanding

Is the displayed timeline invented by the app?

The application events describe actual operations. Native trace metadata comes from the configured Mastra exporter and storage; the two are labelled separately.

Does a trace prove every answer is correct?

No. It is execution evidence that must be compared with the task and returned source data.

Will app-host and Studio runs share process-local state?

They are separate processes. They can inspect the same configured local trace database, while an application's transient event callbacks belong to its own run.

Implemented scope: This app configures actual native tracing and local trace storage. It does not publish telemetry externally, expose hidden chain-of-thought, configure aggregate metrics or replace application tests.

Practical exercise

Compare the successful and missing-record traces. Explain why a completed workflow can still need a corrected task input. Open Studio and inspect the registered workflow.
